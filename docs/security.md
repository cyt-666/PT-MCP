# 安全边界

PT MCP 面向个人自托管。默认只监听回环地址，并要求所有 HTTP 请求携带 Bearer Token。

## 凭据与访问

- 使用 `PT_MCP_TOKEN` 配置服务访问令牌。缺少令牌时，服务不得接受 HTTP 请求。
- 认证覆盖 MCP 初始化、能力发现、工具调用、SSE 读取和会话删除等所有 HTTP 方法。
- 站点 Cookie、API Key、Token 和 qBittorrent 密码只由服务端读取，不进入工具参数或结构化结果。
- 工具调用只接收服务生成的资源引用和配置 ID，不接受任意目标 URL。
- 返回的详情页链接会删除认证查询参数。无法安全清理时返回 `null`。

## 网络部署

本地默认地址是 `127.0.0.1:8000`。Docker Compose 也只把服务端口绑定到宿主机回环地址。

需要远程访问时，应通过 HTTPS 反向代理，并为 MCP SDK 配置精确的 Host 和 Origin allowlist。不要关闭 DNS rebinding 防护，也不要将明文服务直接暴露到公网。

配置的站点地址和 qBittorrent 地址由管理员维护。MCP 调用方不能修改它们。服务应验证站点协议、重定向目标和允许的本地/私有网络访问范围，防止 SSRF。

## SQLite 与并发提交

SQLite 保存资源引用、RSS 快照和下载提交回执。提交前服务持久化意图并占用幂等键；并发请求使用同一 `request_id` 时共享已有状态。

SQLite 事务无法与 qBittorrent API 的提交组成原子事务。服务崩溃或请求超时后可能留下 `unknown` 状态。服务必须先按 hash 核验现状，不能自动重复提交。

单机部署使用一个服务进程。不要让多个无协调的实例同时写同一个 SQLite 文件。需要多副本时，应先替换为支持事务和锁租约的数据库实现。

## 日志与配置

日志仅记录站点 ID、工具名、状态和稳定 hash。不要记录完整 URL、Cookie、认证头、token、种子下载链接或原始异常文本。

`config.yaml`、SQLite 数据目录、`.env` 和 Docker secrets 都可能包含敏感信息，应限制文件权限并排除版本控制。配置示例只包含假值。
